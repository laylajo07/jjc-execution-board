# Vercel 배포 — B(직접설계) 앱

배포 대상은 **B_직접/앱/**(확정 제출작)입니다. 순수 정적 파일(index.html + JS 모듈)이라
빌드 과정 없이 그대로 올리면 됩니다. A_웹페이지/앱, 러너, 회의록 등 나머지는 배포에 포함되지 않습니다.

## 배포하면 뭐가 되고 뭐가 안 되나

- **📋 복붙 모드는 그대로 동작합니다.** 러너 없이 쓰는 방식이라 서버가 필요 없고, 앱은
  기본값이 이미 복붙 모드입니다(`initMode()` → `applyMode(false)`).
- **⚡ 자동 모드는 배포 환경에서 켤 수 없습니다.** 자동 모드는 로컬에 로그인된 Claude Code CLI를
  `claude -p`로 직접 실행하는 방식이라, Vercel 같은 서버리스 환경에서는 애초에 재현할 수
  없는 기능입니다(로컬 프로세스 실행 + 대화형 로그인 필요). 코드가 이미 `/api/health`가
  없으면 자동 모드 전환 자체를 막고 안내 토스트를 띄우도록 되어 있어 별도 처리가 필요 없습니다.
- **"↗ A안 비교" 버튼은 배포 도메인에서 자동으로 숨겨집니다.** 이 버튼은 `localhost:8788`(로컬 A 러너)로
  이동하는 기능이라 공개 배포 상태에선 항상 실패하므로, `location.hostname`이 localhost/127.0.0.1/
  file:// 가 아니면 숨기도록 처리했습니다(오늘 배포 준비하며 추가).

## 사전 준비 (최초 1회)
```bash
# Vercel 계정 필요(무료 티어로 충분). CLI는 별도 설치 없이 npx로 바로 씀.
```

## 배포 방법 — B_직접/앱을 프로젝트 루트로 삼아 배포
`B_직접/앱` 폴더 자체를 Vercel 프로젝트로 연결하는 게 제일 단순합니다(모노레포 라우팅 설정 불필요).

```bash
cd B_직접/앱
npx vercel login      # 브라우저로 로그인(최초 1회) — 대화형이라 사용자가 직접 실행해야 함
npx vercel            # 첫 배포 = 프리뷰. 아래 질문에 답하면 됨:
#   Set up and deploy "B_직접/앱"? → Y
#   Which scope? → 본인 계정/팀 선택
#   Link to existing project? → N (최초엔)
#   Project name? → 예: jjc-board (한글 폴더명 "앱" 대신 영문 슬러그 추천)
#   In which directory is your code located? → ./ (이미 B_직접/앱 안에 있으므로 그대로)
#   원하는 설정 감지 질문들 → 전부 기본값(정적 사이트라 빌드 커맨드 없음)
npx vercel --prod     # 프로덕션 배포(실제로 공유할 URL)
```

배포가 끝나면 터미널에 `https://<project-name>.vercel.app` 형태의 URL이 출력됩니다.

## 코드 수정 후 재배포
```bash
cd B_직접/앱
npx vercel --prod
```
그때그때 바뀐 파일만 다시 올라갑니다. `.vercelignore`가 `결과/`(로컬 테스트용 분석 결과 캐시)를
제외하므로 배포물에는 포함되지 않습니다.

## 참고
- Git 연동(GitHub 푸시 시 자동 배포)은 이 저장소가 로컬 전용(원격 없음)이라 이번엔 CLI 직접 배포로
  진행합니다. 나중에 GitHub에 올리면 Vercel 대시보드에서 리포를 연결해 자동 배포로 전환할 수 있습니다.
- `문서/실행방법.md`는 로컬(A·B 동시 비교, 자동 모드 포함) 실행법이고, 이 문서는 **공개 배포(B 단독,
  복붙 모드만)** 기준입니다 — 서로 다른 시나리오라 혼동하지 마세요.
