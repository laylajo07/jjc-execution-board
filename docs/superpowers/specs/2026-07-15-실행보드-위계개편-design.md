# 회의록 실행보드 — 시각적 위계 개편 & 크리티컬 패스 다이어그램 설계

> 2026-07-15 · 대상: `A_웹페이지/앱/`, `B_직접/앱/`, `러너/{py,ts}`

## 1. 문제

### 1-1. 위계가 없다 (사용자 지적)

서머리 → 부서별 실행항목 → 의사결정 필요 → 크리티컬 패스 → 갭/가정 → 부서별 메시지.
6개 섹션이 **전부 비슷한 밀도의 텍스트 블록**이라 어디를 먼저 봐야 할지 눈에 들어오지 않는다.
"다 중요하다"는 곧 "아무것도 중요하지 않다"와 같다.

### 1-2. 크리티컬 패스가 다이어그램이 아니다

번호 + 화살표 텍스트 나열이라 "병목이 여기다"가 꽂히지 않는다.
본질이 의존 그래프인데 1차원 리스트로 눌러놨다.

### 1-3. (조사 중 발견) 지금 데이터로는 다이어그램을 그릴 수 없다

`B_직접/앱/결과/샘플01_결과.json` 실측:

| 항목 | 값 |
|---|---|
| 전체 의존 관계(edge) | 8 |
| `blocked_by` 문자열이 노드 `task`와 정확히 일치 | **1** |
| 불일치 | **7** |

원인: `blocked_by`가 노드 id가 아니라 **매번 다른 표현의 자유 텍스트**.

- step5 `blocked_by: 'v2 모델 확정'` ↔ step2 `task: 'v2 모델 재학습 → AUC 0.85 달성'` — 같은 노드, 다른 이름
- step7 `blocked_by: 'v2 모델 성능 확정'` — 같은 노드, 세 번째 이름
- step8 `blocked_by: ['PoC 데모환경','샘플리포트']` — step6 한 노드(`'PoC 데모환경·샘플리포트 준비'`)를 둘로 쪼갬
- step9 `blocked_by: '제품 스펙 확정'` — **대응 노드가 아예 없음**
- step4 `blocked_by: '가격 단가표 초안'` ↔ step3 `task: '가격 단가표 초안 작성'` — '작성' 한 단어 차이

지금 화면이 멀쩡해 보이는 이유는 렌더러가 이 문자열들을 **칩으로 찍기만 하고 연결하지 않기 때문**이다.
화살표를 그리는 순간 7개가 끊긴 선/틀린 선으로 드러난다.

**근본 원인**: `blocked_by`와 `blocks`가 둘 다 모델이 쓰는 자유 텍스트다.
같은 화살표 하나를 양쪽 끝에서 각자 다른 말로 적게 해놨으니 안 맞는 게 정상이다.

### 1-4. (조사 중 발견) 병목이 계산값이 아니라 모델의 의견

현재 `bottleneck: true`(step 2·4·7)는 모델이 직접 찍은 값이다. 그래프에서 유도한 값이 아니라 근거를 댈 수 없고 검증도 안 된다.

### 1-5. (조사 중 발견) 러너가 스트리밍을 안 한다 — 문서와 불일치

러너 `py`/`ts` 모두 `claude -p` 호출 시 `--output-format stream-json --verbose`를 넘기지 않는다.
이 플래그가 없으면 `claude -p`는 **완료 시점까지 아무것도 출력하지 않고 마지막에 통째로 뱉는다**.

실측:
- 실제 분석 프롬프트로 CLI 직접 실행 → 400초 타임아웃까지 **출력 0바이트** (부분 출력 전혀 없음)
- 화면에는 "생성되는 내용이 아래에 실시간으로 표시됩니다"라고 표시 중 → **거짓 안내**

문서의 틀린 서술 2건:
- `문서/평가_비교.md`: "결과 스트리밍(SSE): 러너가 `claude -p` 출력을 실시간 전달" → 사실 아님
- `README.md`: "`claude -p`는 매 요청 세션을 새로 부팅해 **모델과 무관하게 1~3분**" → 사실 아님.
  짧은 프롬프트("Say OK only")는 **5초**에 완료. 병목은 세션 부팅이 아니라 **출력 길이**.

## 2. 결정 사항

| 항목 | 결정 |
|---|---|
| 크리티컬 패스 표현 | **A · 계층형 DAG** (열 = 의존 깊이, 좌→우) |
| 섹션 위계 | **H1 · 히어로 + 단계적 축소** (3단 위계) |
| 적용 범위 | **A·B 앱 둘 다** |
| 스트리밍 수정 | **이번에 같이 처리** |

### A·B 둘 다 개편할 때의 공정성 선

A의 시스템 프롬프트는 사내 웹페이지가 만들어준 "A의 두뇌"다. 여기에 임의로 손대면 A의 정체성이 깨진다.

**선긋기**: JSON 출력 계약은 *앱이 데이터를 받아먹는 인터페이스*이지 *분석 능력*이 아니다.

- **양쪽에 동일 적용**: id 스키마, `blocked_by_external`, `blocks`/`bottleneck` 제거
- **손대지 않음(= 비교 대상)**: A의 본부 나열 vs B의 매핑 규칙표 / A의 '확인 필요' 단일 vs B의 확정·추정·확인필요 3단계 / B의 상대→절대 날짜 환산 / B의 Top3·자기검증

이 선긋기를 `문서/평가_비교.md`에 명시한다. 기존에 이미 "공정성을 위해 A의 앱도 같은 코크핏 형태로 제작"한 선례와 같은 성격의 조치다.

## 3. 데이터 계약 (스키마)

### 3-1. 원칙: 같은 사실은 한 군데만 적는다

모델이 적을 것을 줄이면 틀릴 것도 줄어든다.

| 필드 | 조치 | 이유 |
|---|---|---|
| `blocked_by` | **id 참조로 변경** | 자유 텍스트 → 매칭 실패 0 |
| `blocked_by_external` | **신설** | 노드가 아닌 선행을 정직하게 보존 |
| `blocks` | **제거** (렌더러가 역산) | `blocked_by`의 역함수. 둘 다 적게 하면 모순 발생 |
| `bottleneck` | **제거** (렌더러가 계산) | 모델의 의견 → 그래프에서 유도한 검증가능한 값 |
| `step` | **제거** (렌더러가 위상정렬) | 순서도 `blocked_by`에서 파생된다. 남겨두면 순서의 출처가 둘이 되어 `blocks`와 같은 모순이 재발 |

**표시 순서 정의**: 위상정렬 결과. 같은 `depth` 안에서의 동점은 **원본 배열 index 순**으로 깬다(모델이 적은 순서를 존중하면서 결정적).

### 3-2. 새 스키마

```json
"sequence": [
  {"id":"T2","task":"v2 모델 재학습 → AUC 0.85 달성","dept":"CB본부",
   "blocked_by":[], "blocked_by_external":[]},
  {"id":"T5","task":"API 응답속도 최적화·배포","dept":"ICT본부",
   "blocked_by":["T2"], "blocked_by_external":[]},
  {"id":"T9","task":"마케팅 브로셔·랜딩 제작","dept":"마케팅본부",
   "blocked_by":[], "blocked_by_external":["제품 스펙 확정"]}
]
```

모델이 적는 것은 **작업·부서·선행 셋뿐**이다. 순서·후행·병목·깊이는 전부 여기서 파생된다.

### 3-3. `blocked_by_external`이 필요한 이유

`'제품 스펙 확정'`은 실재하는 선행인데 작업 목록에 없다.

- 억지로 노드화 → 회의록에 없는 작업을 **지어내는 것** (핵심 원칙 위반)
- 그냥 버림 → 정보 소실
- **`blocked_by_external`로 분리 → 점선 스텁으로 "뭔가를 기다리는데 그게 뭔지 회의록에 없다"를 드러냄**

지금 앱이 조용히 뭉개던 것을 오히려 표면화한다.

### 3-4. 프롬프트 자기검증 스텝 (A·B 공통 추가)

> `blocked_by`의 모든 id가 `sequence`에 실제로 존재하는지 확인하라.
> 존재하지 않으면 그 항목을 `blocked_by_external`로 옮겨라. 없는 id를 남기지 마라.

## 4. 그래프 엔진 (순수 함수)

### 4-1. 왜 분리하나

여기가 **조용히 틀릴 수 있는 유일한 지점**이다. 1-3이 정확히 그 사고였다 — 화면은 멀쩡한데 데이터가 안 맞았고, 렌더러가 연결을 안 했기 때문에 아무도 몰랐다.

DOM을 만지지 않는 순수 함수로 두면 브라우저 없이 fixture로 검증할 수 있다.

### 4-2. 인터페이스

```
buildGraph(sequence) -> {
  nodes:   [{id, task, dept, depth, downstream, isBottleneck, externals:[string], x, y}],
  edges:   [{from, to, critical}],
  warnings:[{type:'cycle'|'unresolved'|'empty'|'single', detail}],
  stats:   {edgeTotal, edgeResolved, mode:'id'|'fuzzy'}
}
```

- 입력: 정규화된 `sequence` 배열 하나
- 출력: 좌표까지 계산된 그래프. 렌더러는 이걸 그리기만 한다
- 결정적(deterministic). 같은 입력 → 같은 출력

### 4-3. 계산 규칙

- **후행(`blocks`)**: `blocked_by` 역산
- **깊이(`depth`)**: 루트로부터의 **최장 경로**. 모든 선행보다 반드시 뒤에 놓이게 함 (최단 경로를 쓰면 선행보다 앞에 놓이는 노드가 생김)
- **병목(`downstream`)**: 도달 가능한 후행 집합의 크기(전이 폐포). 최댓값 노드(동점 포함)가 `isBottleneck`
- **크리티컬 엣지**: 병목 노드에서 나가는 엣지 → 빨간색
- **순환 의존**: DFS로 탐지. 발견 시 레이아웃용으로 back edge만 제거하고 `warnings`에 `{type:'cycle', detail:'T3→T7→T3'}` 추가. **절대 조용히 버리지 않는다**
- **좌표**: `x = depth × (노드폭 + 간격)`. `y`는 열 내 슬롯 배정 — 선행들의 y 평균(barycenter) 기준 1-pass 정렬로 교차 완화. 노드 15개 내외라 이 정도로 충분

### 4-4. 구버전 데이터 fallback (`mode:'fuzzy'`)

id가 없는 기존 결과 JSON도 렌더링해야 한다.

1. `blocked_by` 문자열을 노드 `task`와 대조
   - 정규화: 소문자화, 공백·특수문자(`→·()` 등) 제거, 후행 접미(`작성·확정·준비·검토·완료·진행`) 1회 절단
   - 점수: **문자 bigram 집합의 포함 계수(overlap coefficient)** = `|A∩B| / min(|A|,|B|)`
   - **0.5 이상**이면서 **1등이 2등보다 0.15 이상 높을 때만** 연결. 애매하면 연결하지 않는다
2. 임계값 미달 또는 동점 → `blocked_by_external` 스텁으로 강등

> **Jaccard가 아니라 포함 계수인 이유** (실측):
> `'v2 모델 확정'` vs `'v2 모델 재학습 → AUC 0.85 달성'` — 같은 노드인데 뒤쪽이 훨씬 길다.
> Jaccard = 3/16 = **0.19** → 연결 실패. 포함 계수 = 3/5 = **0.60** → 연결 성공.
> 짧은 별칭이 긴 정식명칭을 가리키는 게 이 데이터의 지배적 패턴이라 포함 계수가 맞다.
> 단어 토큰이 아니라 문자 bigram을 쓰는 이유는 한국어 띄어쓰기가 들쭉날쭉하기 때문.

> **fuzzy는 완전 복구가 아니다** (실측): 위 규칙으로도 `'v2 모델 성능 확정'`(포함계수 0.43)은 연결되지 않는다.
> 8개 중 일부만 살아난다. **이것이 정상이고 의도된 동작이다** — 스키마 개편이 근본 해결이고,
> fuzzy는 이미 저장된 구버전 결과 파일을 열었을 때 "그래도 볼 수 있게" 해주는 안전망일 뿐이다.
> 그래서 고지 문구로 몇 개가 연결됐는지 반드시 밝힌다.
3. 화면에 조용히 고지: **"구버전 결과 · 의존관계 8개 중 1개만 연결됨"**

성능이 떨어졌으면 떨어졌다고 말한다. 조용히 그럴듯한 화살표를 그리는 것이 최악이다.

## 5. 렌더러 · 위계 (H1)

```
┌─ Tier 1 · 히어로 ────────────────────────┐
│ 한 줄 요약 (크게)                          │  3초 안에 "뭐가 막혔나" 종료
│ 지금 할 일 Top 3 (3칸)                     │
│ 크리티컬 패스 DAG (크게)                    │
└──────────────────────────────────────────┘
┌─ Tier 2 · 부서별 실행항목 (6 카드, 중간 밀도) ┐
└──────────────────────────────────────────┘
┌─ Tier 3 · 기본 접힘 + 개수 배지 ────────────┐
│ ▸ 의사결정 필요 (4)                         │
│ ▸ 확인 필요 · 가정 (11)                     │
│ ▸ 부서별 공유 메시지 (6)                     │
└──────────────────────────────────────────┘
```

- **순서 변경**: 크리티컬 패스를 4번째 → **맨 위 히어로 안으로**
- **공유 메시지 접기**: 복사할 때만 필요한 물건. 6개가 길게 늘어져 보드를 잡아먹던 문제 해소
- 라이트/다크 유지

## 7. 엣지 케이스

| 상황 | 처리 |
|---|---|
| `sequence` 없음/빈 배열 | DAG 섹션 숨김 + "진행 순서를 뽑을 수 없었습니다" + 이유 |
| 노드 1개 | 다이어그램 대신 한 줄 텍스트 |
| 전부 external (내부 엣지 0) | 그래프를 그대로 그린다 — 전원 depth 0의 단일 열 + 각자의 점선 스텁. 별도 목록 화면을 만들지 않는다(같은 정보를 두 가지로 그리는 셈이라 얻는 게 없다). `unresolved` 경고로 몇 개가 안 붙었는지 알린다 |
| 순환 의존 | back edge 제거 후 레이아웃 + 경고 카드 |
| 노드 20개 초과 | 가로 스크롤 컨테이너 (노드 폭 고정) |
| 빈 회의록 / 무의미 입력 | 기존 처리 유지 |

## 8. 검증 계획

**증거 없는 완료 선언 금지.** 1-3·1-5가 "검증 완료"로 적혀 있었으나 사실이 아니었던 전례가 있다.

1. **그래프 엔진 fixture 테스트** (브라우저 불필요)
   - 샘플01~04 + 인위적 순환 fixture + 전부-external fixture + 빈 fixture
   - **샘플01 기대값**: 내부 엣지 8개 전부 연결(`edgeResolved === edgeTotal`) · `isBottleneck` = `v2 모델 재학습` · `downstream === 4`
2. **구버전 fallback 테스트**: 현재 `결과/샘플01_결과.json`(id 없음) 투입 → `mode:'fuzzy'` · 고지 문구 노출 확인
