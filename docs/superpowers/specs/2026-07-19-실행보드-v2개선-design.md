## 0. 배경

07-15 개편으로 크리티컬 패스가 **계층형 SVG DAG**(`graph.js` + `dag-view.js`)로 이미 구현됐다(작업 트리, 미커밋).
이번 v2는 그 위에 얹는 **세 가지 UI 개선(#2·#3·#4)**이며, 하나의 스펙으로 묶어 A·B 양쪽에 동일 적용한다.

| 2 | 크리티컬 패스를 플로우 다이어그램으로, 병목 색 강조, **노드 클릭 시 담당/기한/상태** 표시 | 다이어그램·병목 강조는 **이미 됨**. 노드는 작업명·부서·병목경고만 표시, **클릭 상호작용 없음** |

### 1-1. 왜 SVG 유지 (mermaid 미채택)

mermaid는 CDN 의존이라 **오프라인 `file://` 더블클릭이 깨진다**(07-15 설계가 명시한 제약). 또 병목 커스텀 색·외부 선행 점선 스텁·노드별 리치 클릭 패널을 붙이기 어려워, 지금 있는 기능이 **회귀**한다. 기존 SVG는 이미 결정적 레이아웃·라이트/다크·부서색을 갖췄다.

### 1-2. 왜 프롬프트를 손대지 않나 (담당/기한/상태 조인)

07-15 설계 3-1 원칙 **"같은 사실은 한 군데만 적는다"**. 담당·기한·상태는 `action_items`가 유일 출처다. 이를 `sequence` 노드에도 적게 하면 모델이 같은 사실을 두 번 쓰게 되어 **불일치가 재발**한다(07-15 §1-3의 그 사고). 따라서 **렌더 시점에 조인**한다.

**조인 실현성(실측 구조 확인):** `sequence.task`는 대체로 `action_item.what` + 괄호 수식어 패턴이다.
예) 노드 `"…v2 … 재학습 (…목표)"` ↔ action_item `"…v2 … 재학습"`.
`graph.js`의 `normalize()`가 괄호·공백·특수문자를 제거하고 `containment()`(포함계수)로 비교하면, 짧은 `what`이 긴 `task`에 거의 포함되어 min-분모 포함계수가 높게 나온다 → 강하게 매칭. 매칭 실패 시 우아하게 축약(아래 3-2).

## 2. 아키텍처 — 모듈 분해

기존: `graph.js`(순수: sequence→그래프) · `dag-view.js`(순수: 그래프→SVG 문자열) · `index.html`(DOM/상호작용).

**신규 순수 모듈 `board-derive.js`** 를 추가한다. "그래프 + 보드 데이터(action_items, gaps) → 뷰모델 파생"이라는, graph도 view도 아닌 제3의 책임을 담는다.

```
buildDetailMap(graph, byDepartment) -> { [nodeId]: {owner, due, status, basis, matched:boolean} }
rankItems(graph, items)             -> [{ text, cpScore, deptSpan, downstream, _i }]  // 우선순위 desc 정렬
```

- **순수(DOM 접근 없음)**. fixture로 브라우저 없이 검증 가능 — 07-15 §4-1이 "조용히 틀릴 수 있는 유일한 지점"이라 지적한 그 자리다.
- **A·B 바이트 동일**. 기존 `graph.js`/`dag-view.js`와 같은 동일성 테스트로 드리프트 차단.
- 전역 이름은 `root.BoardDerive`(graph.js=`Graph`, dag-view.js=`DagView`와 동일 패턴). graph.js 뒤에 로드 — `Graph.containment`를 재사용한다.
- `graph.js` 노출: 검증된 내부 함수 `normalize`·`containment`를 api에 **추가 노출만** 한다. 기존 동작·테스트 불변. 매칭 로직을 두 벌 만들어 어긋나는 걸 막는다.

## 3. #2 — 노드 클릭 → 사이드 패널

### 3-1. 데이터 조인

`board-derive.buildDetailMap(graph, byDepartment)`:
1. 각 노드에 대해 **같은 부서 우선** → 전체 순으로 `action_items[].what`과 `G.containment(node.task, what)` 최대값 후보를 찾는다.
2. 최고 점수 ≥ **0.5**면 `{owner, due, status, basis, matched:true}`. 미달이면 `{matched:false}`.
3. 결정적(같은 입력 → 같은 출력). 동점은 원본 배열 순으로 깬다.

### 3-2. 패널 본문 (`dag-view.nodePanelHtml(node, detail, graph)` — 순수 문자열)

- **작업명**(제목) · **부서 배지**(부서색, `deptColor`)
- **담당 / 기한 / 상태** — 상태는 색 태그(확정=ok·추정=est·확인필요=chk). `detail.matched===false`면 담당·기한·상태 줄 대신 *"담당·기한은 부서 표 참조"* 미주 + 나머지 그래프 정보만.
- **병목**이면: `⚠ 병목 · 후행 N개 차단` (N = `node.downstream`)
- **선행**: `graph.edges` 중 `to===node.id`인 `from`을 노드 task로 표시. **외부 선행**: `node.externals`(점선 스텁 라벨).
- `basis`가 있으면 근거 한 줄.

### 3-3. 상호작용 (index.html)

- `render()`가 SVG 삽입 후 `const detail = BoardDerive.buildDetailMap(g, d.by_department)`.
- 드로어 DOM `.node-panel`(초기 닫힘) 배치.
- SVG의 `.dag-n[data-id]`에 클릭 + `keydown`(Enter/Space) → id로 노드/detail 조회 → `nodePanelHtml` 채우고 패널 열기 + 해당 노드 `.sel` 강조.
- 닫기: 닫기 버튼 · `Esc` · 오버레이 클릭.
- 노드는 `tabindex=0 role=button`이라 **키보드 포커스·조작** 가능. 클릭 시 `.focus()`로 `:focus-visible` 링도 표시.

### 3-4. 레이아웃 & 스타일

- 데스크톱: **우측 슬라이드 드로어**. 모바일(≤600px): **하단 시트**.
- **라이트/다크 둘 다** 스타일(`--surface`/`--line`/`--shadow` 토큰 재사용). `prefers-reduced-motion`은 전역 `*{animation:none;transition:none}`로 이미 존중됨.
- **선택 강조 vs 병목 빨강 구분**: 선택 노드는 first `<rect>` stroke를 `--primary`·width 3으로. 병목의 빨강 **배경**과 `⚠` 경고 라벨은 그대로 유지되어 "병목이면서 선택됨"이 동시에 읽힌다.

## 4. #3 — 확인필요·가정 우선순위 압축

### 4-1. 랭킹 (`board-derive.rankItems(graph, items)` — 순수)

각 문자열 항목 `g`에 대해:
- **매칭 노드 m**: `nodes[].task` 중 `containment(g, task)` 최고. 매칭 없으면 외부 스텁 라벨도 시도.
- **랭킹 임계값 0.35** (조인의 0.5보다 느슨). 근거(실측): gap 문자열은 `"…재학습 **완료 기한 미기재**"`처럼 노이즈 어미가 붙어 포함계수가 희석된다 — 정작 병목 T2를 가리키는 `"v2 모델 재학습 완료 기한 미기재"`가 0.46으로 0.5 미달. **랭킹은 소프트 신호**(항상 최적 노드 1개만 사용, 오정렬은 저위험)라 느슨한 임계값이 허용되고, 특정 담당/기한을 드러내는 조인(0.5, 하드)과는 성격이 다르다.
- 정렬 키(모두 desc, 마지막만 asc):
  1. **`cpScore`**: `m.isBottleneck`이면 2 · `m.downstream>0`(또는 외부 스텁 매칭)이면 1 · 그 외/미매칭 0 → **"크리티컬 패스에 걸린 항목"** 최상위.
  2. **`deptSpan`**: m의 후행(도달가능) 집합에 등장하는 **distinct 부서 수**(`graph.edges`로 계산). → **여러 부서를 막는 항목 > 단일 부서 국한**.
  3. **`downstream`**: m의 후행 수.
  4. **원본 index** asc → 안정 정렬(결정적).

**샘플01 gaps 실측 순서(인수 기준):** `v2 재학습 완료 기한 미기재`(T2 병목, cpScore 2) → `API 최적화 기한 미기재`(T5, span 2) → `가격 단가표 기한 미확정`(T4, span 1) → `제품 스펙 확정 미정`(외부 스텁, cpScore 1) → `이사회 보고 순서 충돌`(T7, downstream 0) → `데사팀 채용 별건 보류`(미매칭, 꼴찌). 즉 병목 gap 최상위·별건 gap 최하위.

### 4-2. 렌더 (index.html)

- 섹션 03 게이트는 기존대로 `gaps.length || assumptions.length`.
- 확인필요·가정 **각각** `rankItems`로 정렬 → 상위 **5개**는 항상 노출, 나머지는 **`<details><summary>더보기 (+N)</summary>…</details>`** 로 접기(네이티브·접근성·무JS). 항목 ≤5면 더보기 없음.
- 칩 스타일은 기존 `.chip.gap`/`.chip.asm` 재사용.

## 5. #4 — 부서별 카드: 조건부 섹션 & 스캔성

### 5-1. 조건부 렌더 — 이미 구현됨

`tblAI`/`tblDoc`/`tblDec`는 빈 리스트에 `''`를 반환한다. 세 섹션이 모두 비었을 때만 "추출된 항목 없음" 폴백이 뜬다. 즉 **데이터 있는 섹션만 렌더**는 A·B 양쪽에 이미 동작한다(#2 다이어그램처럼 "현재 항상 렌더" 서술은 커밋 이전 상태).
→ 추가 작업: 이 동작을 **회귀 방지 스냅샷 테스트**로 못 박는다(빈 섹션 미출력, 전부 빈 부서만 폴백).

### 5-2. 카드 높이/여백 정리 (실제 작업, CSS만)

- 현재 `.depts{grid-template-columns:repeat(auto-fill,minmax(360px,1fr))}`는 grid 기본 `align-items:stretch`라, 같은 행에서 1-섹션 카드가 3-섹션 카드 높이에 맞춰 늘어나 **하단 여백이 들쭉날쭉**하다.
- **`.depts{align-items:start}`** → 각 카드 자연 높이, 낭비 여백 제거.
- `.dept__b`/`.block` 수직 리듬 일관화(섹션 수와 무관하게 헤더–첫블록–블록간 간격 동일)로 1개·3개 카드가 같은 규칙으로 스캔되게.
- 라이트/다크 불변. **로직·데이터 변화 없음** — 그래프/board-derive와 무관한 순수 CSS.

## 6. 엣지 케이스

| 상황 | 처리 |
|---|---|
| `sequence` 없음/빈 배열 | DAG 섹션 숨김(기존). 패널·조인 자체가 없음 |
| 노드 1개 | 기존 한 줄 텍스트 유지, 클릭 패널 미적용 |
| 조인 실패(매칭 없음) | 패널은 그래프 정보만 + "부서 표 참조" 미주 |
| gap이 노드에 매칭 안 됨 | cpScore 0·deptSpan 0 → 자연히 하위로 접힘 |
| gaps/assumptions ≤ 5 | 더보기 토글 미노출 |
| 순환 의존 | 07-15 처리 유지(back edge 제거 + 경고). downstream 계산 영향 없음 |

## 7. 검증 계획

**증거 없는 완료 선언 금지**(07-15 §8).

1. **board-derive fixture 테스트**(브라우저 불필요, `테스트/graph.test.js`)

3. **A·B 동일성**: `graph.js`·`dag-view.js`·`board-derive.js` 바이트 동일.
4. **#4 조건부 렌더 스냅샷**: 섹션 일부만 있는 부서 → 빈 섹션 미출력, 전부 빈 부서만 폴백.
