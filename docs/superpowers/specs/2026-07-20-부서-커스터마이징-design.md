# 부서 커스터마이징 설계

> 2026-07-20 · 대상: `A_웹페이지/앱/`, `B_직접/앱/`, `러너/{py,ts}` · 선행: [실행보드 v2 개선](./2026-07-19-실행보드-v2개선-design.md)

## 0. 배경 · 범위

사용자(PM) 요청 — 두 파트, 사용자가 "모두"로 최대 범위 확정:
- **A. 입력 시**: 표준 부서 체계(6본부)는 **유지**하되, 사용자가 (a)**새 부서명**과 (b)**원문→본부 매핑 규칙**을 **추가**.
- **B. 산출 후**: 결과 보드에서 부서를 **이름 변경·병합·순서 이동·숨김·완전 삭제·새 부서 추가**.

**적용:** A·B 앱 둘 다 · 복붙 모드 + 자동 모드(러너 포함) · 오프라인 `file://` 유지(신규 CDN 금지) · 순수 로직은 A·B 바이트 동일 모듈.

## 1. Part A — 입력 시 부서 옵션 추가

### 1-1. 데이터 (localStorage `jjc-dept-config`, 오리진별)
```json
{ "customDepts": ["신설본부", "R&D센터"],
  "customMappings": [{ "raw": "우리팀", "dept": "CB본부" }, { "raw": "AI실", "dept": "R&D센터" }] }
```

### 1-2. UI — 헤더 **⚙️ 부서 설정** 버튼 → 패널(오버레이, 기존 `.cmp-overlay` 패턴 재사용)
- **표준 부서**(읽기전용 칩): CB본부·ICT본부·경영본부·법무실·고객솔루션본부·사업성장본부
- **커스텀 부서**: 입력 + [추가] → 목록(각 삭제 ✕)
- **매핑 규칙**: `원문 표기` 입력 + `→ 부서` 드롭다운(표준+커스텀) + [추가] → 목록(삭제 ✕)
- [저장] → localStorage. 다음 분석부터 반영. (닫기·Esc·오버레이 클릭)

### 1-3. 프롬프트 주입 — 신규 순수 함수 `boardCustom.deptConfigToPrompt(config)`
설정을 아래 텍스트 블록으로 변환(비면 빈 문자열):
```
[사용자 추가 부서 — 표준 본부와 동일하게 취급]
- 추가 부서: 신설본부, R&D센터
- 매핑(우선 적용): "우리팀"→CB본부, "AI실"→R&D센터
표준 6본부 + 위 추가 부서를 모두 사용 가능. 매핑 규칙을 표준화보다 우선한다.
```
- **복붙 모드**: `fullPrompt(note)`가 SYS 뒤에 이 블록을 append.
- **자동 모드**: `/api/analyze` 요청 body에 `deptConfig` 동봉 → 러너가 AGENT.md 뒤에 이 블록 append(3절).

## 2. Part B — 산출 후 부서 편집

### 2-1. 신규 순수 모듈 `dept-edit.js` (A·B 바이트 동일, DOM 없음, fixture 테스트)
정규화된 `by_department` 배열에 대한 순수 변환 — 새 배열 반환(불변):
```
renameDept(list, idx, name) → list         // 이름 변경
moveDept(list, idx, dir)    → list         // 순서(dir: -1/+1)
setHideDept(list, idx, hidden) → list       // 숨김 토글(_hidden 플래그)
deleteDept(list, idx)       → list         // 부서 + 항목 제거
mergeDepts(list, fromIdx, toIdx) → list     // from의 action_items·documents·decisions_needed를 to에 이어붙이고 from 제거
addDept(list, name)         → list         // 빈 부서 카드 추가
```

### 2-2. render 리팩터 (편집분 보존)
현재 `render(raw)`가 내부에서 `normalize`. 편집분을 유지하려면 정규화 결과를 상태로 둔다:
- `render(raw)` → `renderBoard(normalize(raw), raw)`
- `renderBoard(d, raw)`: `lastBoard=d; lastData=raw||lastData;` 이후 **d로 h 조립·렌더·배선**(기존 로직 이관).
- 편집 시: `lastBoard.by_department = 편집(dept-edit)`; `renderBoard(lastBoard, lastData)`.
- **JSON 저장·마크다운 복사**: 편집 반영을 위해 `lastBoard` 기준으로 재구성(숨김 부서는 제외).

### 2-3. UI — "부서별 실행 항목" 아코디언 헤더에 **[부서 편집]** 토글
편집 모드 on 시 각 부서 카드에:
- 부서명 → **인라인 input**(변경)
- **↑ ↓**(순서) · **👁 숨김**(토글, 흐리게+제외 표시) · **✕ 삭제** · **병합 ▾**(대상 부서 선택 드롭다운)
- 그룹 하단 **[+ 부서 추가]**(이름 입력 → 빈 카드)
- 편집 즉시 `lastBoard` 갱신 + 재렌더. (아코디언은 열린 상태 유지)

## 3. 러너 변경 (`러너/py/server.py`, `러너/ts/server.ts`)
- `do_POST`/POST 핸들러: `body.deptConfig`(JSON) 읽어 `deptConfigToPrompt` 동일 규칙으로 텍스트화해 프롬프트에 append.
- **주입 안전**: 문자열만 허용·개행/제어문자 정리, 과도 길이 컷. 없으면 무동작(기존과 동일).
- SSE·파싱부 불변.

## 5. 엣지 케이스
| 상황 | 처리 |
|---|---|
| 커스텀 설정 없음 | 프롬프트 주입 빈 문자열 = 기존과 동일 |
| 병합 대상=자기 자신 | 무시 |
| 부서 0개로 편집 | "부서별 실행 항목" 아코디언 숨김(기존 가드) |
| 숨김 부서 | 화면 흐리게 + JSON/MD 출력 제외 |
| 잘못된 deptConfig(러너) | 무시하고 기본 프롬프트 |
| A(구스키마)/B(신스키마) | 편집은 **정규화된 by_department**에 적용 → 스키마 무관 |

## 6. 검증
1. **순수 테스트**(`node --test`): dept-edit 6종(불변·병합·순서·삭제·추가), `deptConfigToPrompt`(추가/매핑 텍스트), A·B 바이트 동일.
2. **러너 파라미터 테스트**: deptConfig가 프롬프트에 append되는지(py 파서 단위).
3. **Playwright**: (A) 부서설정에서 커스텀 부서+매핑 추가→복붙 프롬프트에 포함 확인, (B) 편집 모드에서 이름·병합·순서·숨김·삭제·추가 각각 보드·JSON 반영. 라이트/다크. A·B 둘 다.

## 7. 범위 밖
- 항목(action_item) 단위 이동/편집(부서 단위만)
- 커스텀 설정 서버 동기화(브라우저 localStorage만)
- 표준 6본부 자체 삭제(추가만; 표준은 유지)

## 8. 단계 (구현 순서)
1. `board-custom.js`(deptConfigToPrompt+저장) + 테스트
2. `dept-edit.js`(편집 6종) + 테스트
3. index.html: render 리팩터(renderBoard 분리)
4. index.html: ⚙️ 부서설정 패널 + 복붙 프롬프트 주입 (Part A)
5. 러너 py/ts: deptConfig 반영 (Part A 자동)
6. index.html: [부서 편집] 모드 (Part B)
7. 통합 검증(Playwright A·B)
