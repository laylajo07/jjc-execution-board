# 프로젝트 히스토리 설계 (지시사항 13)

> 2026-07-21 · 대상: `A_웹페이지/앱/`, `B_직접/앱/` · 위임: 사용자 "너가 권장하는 대로 끝까지"

## 0. 요구 (지시사항 13)
- 회의록 입력 전 "프로젝트 선택 또는 새로 만들기" 옵션
- 같은 프로젝트에 회의록 **여러 번 누적 저장**
- 회차별 실행보드를 **시간순**으로 열람
- 회차 간 **변경 항목을 색상/태그로 구분**(신규/완료/변경)

## 1. 핵심 설계 결정 (권장안)

**저장: localStorage (오리진별, 클라이언트).** 근거 — 앱이 오프라인 `file://` + 선택적 러너 구조라
서버 없이 동작해야 하고, 이미 dept-config·cmp가 localStorage를 쓴다. 러너 없이도 히스토리가 유지된다.
- 용량 한계(~5MB) 대비: 회차 최대 **20개** 유지(초과 시 오래된 것부터 제거), 초과는 `log`/토스트 고지.
- 키 `jjc-projects`:
```json
{ "current": "<projectId|''>",
  "projects": [
    { "id":"p_...", "name":"", "createdAt":"ISO",
      "rounds": [ { "id":"r_...", "ts":"ISO", "title":"", "raw": { …결과 JSON… } } ] } ] }
```
`raw`는 `lastData`(정규화 전 원본). `ts`는 `updated_at`(있으면) 또는 저장 시각.

## 2. 신규 순수 모듈 (A·B 바이트 동일)

### `project-store.js` — 프로젝트/회차 상태 (순수 변환 + 얇은 저장)
```
loadProjects()                         → state   // localStorage 읽기+sanitize, 없으면 {current:'',projects:[]}
saveProjects(state)                    → bool
createProject(state, name)             → {state, id}   // 불변, 새 프로젝트 추가 + current 설정
renameProject(state, id, name)         → state
deleteProject(state, id)               → state
addRound(state, projectId, round)      → state   // rounds 뒤에 추가, 20개 초과 시 앞에서 제거
setCurrent(state, id)                  → state
getProject(state, id)                  → project|null
```
- 순수·불변·DOM 미접근. localStorage 없으면(Node) 던지지 말고 빈 상태/false.
- `sanitize`: 이름 40자·제어문자 제거(부서 설정과 동일 관심사), rounds 배열 방어.

### `board-diff.js` — 회차 간 변경 판정 (순수)
```
diffBoards(prevBoard, curBoard) → { byKey }   // 정규화된 두 보드 비교
```
- 항목 단위: action_items(+documents+decisions)를 (dept + task/what/topic) 로 매칭(graph.js `containment` 재사용, 임계 0.6).
- 태그:
  - **신규(new)**: cur에 있고 prev에 매칭 없음
  - **완료(done)**: prev에 있고 cur에 매칭 없음, **또는** 매칭되며 상태가 `확정`으로 바뀜
  - **변경(changed)**: 매칭되며 owner/due/status 중 하나라도 달라짐
  - (그 외: 불변 = 태그 없음)
- prev가 없으면(첫 회차) 전부 태그 없음(또는 전부 신규 — 결정: **태그 없음**, 첫 회차는 비교 대상 없음).
- 반환은 cur 항목별 태그 맵. 렌더러가 색/배지로 표시.

## 3. UI (index.html, A·B 동일)

### 3-1. 프로젝트 선택 (입력 콘솔 상단)
- `<select id="projSel">`: 프로젝트 목록 + "— 프로젝트 없음 —". 옆에 **[+ 새 프로젝트]**(이름 입력).
- 선택 시 `current` 갱신 + 그 프로젝트의 회차 히스토리 로드.
- 프로젝트 미선택도 허용(기존처럼 단발 분석). 선택돼 있으면 분석 결과가 그 프로젝트에 **자동 누적**.

### 3-2. 분석 시 회차 저장
- `renderBoard(d, raw)`에서 `raw!=null`(새 분석)일 때, `current` 프로젝트가 있으면 `addRound`.
- 저장 후 히스토리 목록 갱신.

### 3-3. 회차 히스토리 패널
- 결과 영역 또는 콘솔에 "📚 회차 히스토리" 목록: 각 회차 `ts`(fmtUpdatedAt) + title, 시간순.
- 클릭 → 그 회차 `raw`로 `render()` (과거 보드 열람). "현재/과거" 표시.
- 회차 열람 시, **직전 회차와 diff**를 계산해 항목에 신규/완료/변경 배지.

### 3-4. 변경 배지 (색/태그)
- 부서 카드의 할 일/의사결정 항목 옆에 배지: `신규`(초록)·`변경`(주황)·`완료`(회색/취소선).
- 기존 `.tag` 스타일 재사용, 기존 토큰만. 라이트/다크 both.

## 4. 파일 변경 요약
| 파일 | 변경 |
|---|---|
| `{A,B}/앱/project-store.js` | **신규**(바이트 동일): 프로젝트/회차 저장·변환 |
| `{A,B}/앱/board-diff.js` | **신규**(바이트 동일): 회차 간 diff |
| `{A,B}/앱/index.html` | 프로젝트 선택 UI · 회차 저장 배선 · 히스토리 패널 · 변경 배지 |
| `테스트/graph.test.js`(또는 신규) | project-store·board-diff 순수 테스트 |

## 5. 단계 (SDD)
1. `project-store.js` + 테스트 (저장/회차/상한/불변)
2. `board-diff.js` + 테스트 (신규/완료/변경, 매칭, 첫 회차)
3. index.html: 프로젝트 선택 UI + 회차 자동 저장
4. index.html: 회차 히스토리 패널 + 과거 열람
5. index.html: diff 배지(신규/완료/변경) 렌더
6. 통합 검증(Playwright A·B, 라이트/다크)

## 6. 엣지·범위
- 러너 없이도 동작(localStorage). 다른 오리진(A 8788 / B 8787)은 히스토리 분리(설계상 각자).
- 회차 20개 상한, 초과 고지.
- **범위 밖**: 서버 동기화, 프로젝트 공유/내보내기, 항목 단위 수동 편집 히스토리.
- 무프로젝트 사용 흐름은 기존과 동일(회귀 없음).

## 7. 검증
- 순수 테스트(store·diff), Playwright(프로젝트 생성→분석 2회 누적→회차 열람→변경 배지, A·B·라이트/다크), 무프로젝트 회귀.
