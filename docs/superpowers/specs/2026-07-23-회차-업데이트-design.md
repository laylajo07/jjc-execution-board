## 1. 요구 (지시 21–24)

- **21** 보드 열람 중 왼쪽 패널에 그 회차의 **회의록 원문**을 자동 표시하고 사용자가 편집 가능.
- **22** "신규 분석" 버튼과 별도로 **"업데이트"** 버튼 추가 — 현재 회차에 **덮어쓰기 재분석**(새 회차 미생성).
- **23** 업데이트 흐름: 수정 회의록 재분석 → 기존 회차 덮어쓰기 → 그 회차를 baseline으로 참조하는 회차가 있으면 **지시 19 연쇄 재계산 확인**과 동일 처리.
- **24** 업데이트 후 보드 상단에 **"마지막 업데이트: 날짜/시각"**을 **최초 분석 일시와 구분**해 표시.

## 2. 핵심 관찰 / 데이터 모델

현재 회차 레코드는 분석 **결과(raw)** 만 저장하고 **입력 회의록 원문은 저장하지 않는다**. 또 `ts`(처리 시각)는
매 저장(재분석 포함)마다 바뀌어 "최초 분석 일시"를 잃는다. 따라서 두 필드를 추가한다
(`project-store.js`, A·B 바이트 동일):

```
round = { id, roundNo, noteId,
          note,        // ✚ 회의록 원문(입력 텍스트). 공백 보존(collapse 금지), 상한 100000자
          ts,          // 마지막 처리(=업데이트) 시각 — 기존, 매 저장 갱신
          createdTs,   // ✚ 최초 분석 시각. 생성 시 ts와 동일, 재분석(덮어쓰기) 때 보존
          title, raw, baselineNo, baselineStamp }
```

- `sanitizeRound`: `note`는 문자열 강제(제어문자·개행 보존, 길이만 컷) — **cleanText 사용 금지**(원문 포맷 파괴).
  `createdTs`는 문자열(기본 ''). 마이그레이션 시 기존 회차는 note=''·createdTs=''(표시 때 ts로 폴백).
- `addRound`(upsert):
  - **생성**: `createdTs = ts`, `note = 입력 note`.
  - **덮어쓰기(같은 roundNo 존재)**: `createdTs`는 **기존 값 보존**, `ts`만 새 처리시각, `note`·`raw`·`title` 갱신,
    baseline은 null/'' 초기화(기존 동작 유지 — 호출자가 재설정).
  - `round.createdTs`가 인자로 오면 우선(로드/테스트 재현). 없으면 위 규칙.

"업데이트"와 "신규(기존 roundNo 지정)"는 저장상 **동일한 upsert-덮어쓰기**다. 버튼은 대상 roundNo를 어떻게
정하느냐(입력칸 vs 현재 회차)와 의도 표기만 다르다.

## 3. UI 배선 (index.html, A·B 각각)

### 3-1. 원문 자동 로드·편집 (21)
- 회차 히스토리 항목 클릭으로 회차 열람 시: `#noteText.value = round.note`(있으면), `#roundNoInput.value = round.roundNo`,
  업데이트 버튼 활성화, `refreshRoundHint()`.
- `#noteText`는 이미 편집 가능한 textarea → 편집은 자동 지원. 편집한 내용은 업데이트/신규 저장 시 `note`로 반영.

### 3-2. 저장 시 원문 보존
- `renderBoard` 저장 분기에서 `note = $('#noteText').value`를 addRound에 전달.

### 3-3. 신규 분석 vs 업데이트 (22·23)
- 모듈 변수 `pendingUpdateRoundNo`(기본 null). 저장 분기의 대상 roundNo =
  `pendingUpdateRoundNo != null ? pendingUpdateRoundNo : (#roundNoInput 값)`. 저장 후 null로 리셋.
- **업데이트 버튼**(`#updateBtn`): 현재 열람 회차가 있을 때만 활성. 클릭 → `pendingUpdateRoundNo = 현재 회차 roundNo` 설정 후
  현재 모드에 맞는 재분석 트리거:
  - 자동 모드: `analyze()`(수정된 `#noteText`를 러너로 재분석).
  - 복붙 모드: 붙여넣은 결과로 `renderPaste()`(현재 회차에 덮어쓰기 렌더).
- 저장은 기존 경로(renderBoard 저장 분기) → upsert-덮어쓰기 → `maybeCascade(savedNo)`가 지시 19 연쇄를 그대로 수행(23-③).
- 버튼 상태: `currentRoundId`가 있고 그 회차가 현재 프로젝트에 존재하면 업데이트 활성, 아니면 비활성.
  `renderProjHistory`/열람/신규저장 후 `refreshUpdateBtn()` 호출.

### 3-4. 최초 분석 vs 마지막 업데이트 표기 (24)
- `renderBoard`에서 현재 회차(curRound: 저장 직후 또는 열람 중인 회차)를 알면, SUMMARY 상단 표기를:
  - `createdTs`와 `ts`가 다르면(=업데이트된 적 있음): **"최초 분석 {createdTs} · 마지막 업데이트 {ts}"**
  - 같으면(최초 1회): **"분석 {ts}"**
  - 표시 포맷은 `BoardCustom.fmtUpdatedAt`. createdTs가 ''면 ts로 폴백.
- 프로젝트/회차가 없을 때(무프로젝트 즉석 렌더)는 기존 `lastUpdatedIso`(board updated_at) 라인을 유지(회귀 없음).

## 4. A·B 바이트 동일 · 테스트

- `project-store.js` 변경 → A·B 동일 편집, 기존 바이트 동일 테스트가 고정. `board-diff.js`·`board-derive.js` 무변경.
- 신규 단위 테스트(`테스트/project-store.test.js`):
  - `note` 저장·공백/개행 보존·길이 컷.
  - `createdTs` 생성 시 ts와 동일, 덮어쓰기 시 보존·ts만 갱신.
  - `round.createdTs`/`note` 인자 우선 반영, 마이그레이션 기본값('').
- UI(21·22·24)는 브라우저 e2e로 검증(원문 로드·편집→업데이트 덮어쓰기·회차 수 불변·연쇄 확인창·최초/마지막 표기).

- **T2** B index.html: 저장 분기에 note 전달 + `pendingUpdateRoundNo` 대상 roundNo + 저장 후 리셋. 열람 시 note/roundNo 로드.
- **T3** B index.html: `#updateBtn`(자동·복붙) + `refreshUpdateBtn()` 활성 제어 + 클릭 배선.
- **T4** B index.html: SUMMARY 최초 분석/마지막 업데이트 표기(24).

## 6. 비목표 (YAGNI)

- 원문 편집 변경분의 자동 저장(회차에 반영은 오직 신규/업데이트 실행 시). 열람 중 텍스트만 바꾸고 실행 안 하면 저장 안 됨.
- 원문 diff/버전 관리, 러너 없는 자동 모드에서 claude 직접 호출 등은 다루지 않음.
