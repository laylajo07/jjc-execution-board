# 접근법 A — 사내 웹페이지 진행 기록 (6단계 전 과정)

> https://techfin-agent-builder.netlify.app/ · 2026-07-14 · playwright로 직접 조작

## 페이지 구조
`1.시작 → 2.개념 이해 → 3.진단 → 4.아이디어 추천 → 5.Agent 선정 → 6.프로토타입(①정의서 ②프롬프트 ③테스트 ④발표 ⑤Claude Code 개발)`

## 3단계 진단에서 입력한 값
- 트랙: 업무용 Agent / 본부: 경영본부(경영지원)
- 반복업무: 회의 정리·회의록, 보고서·현황 작성 / 하루 2-4시간
- 아이디어: (지시사항 7번 주제 그대로 서술)
- 업로드: `샘플01_불규칙메모.txt` (931자) → 추천 정확도 크게 향상

## 4단계 아이디어 추천 (4개 제시, 회의록 내용을 실제로 읽고 생성)
1. **멀티본부 회의록 액션 구조화 Agent** ← 선택 (주제 정확히 일치)
2. 부서별 맞춤 공유 메시지 자동 발신 Agent
3. 경영진 보고자료 자동 초안 생성 Agent
4. 본부 간 의사결정 순서 추적 대시보드 Agent

→ 추천 품질 우수. 업로드한 회의록의 "대체데이터 법무검토→모델 확정→플랫폼 배포" 의존관계까지 반영.

## 5단계 Agent 선정
- 이름: 멀티본부 회의록 액션 구조화 Agent
- 설명: 공유 메시지 생성 요소를 추가 보강함.

## 6단계 프로토타입

- ② 시스템 프롬프트: 생성됨 → `시스템프롬프트.md` 에 원본 저장

- ④ 발표: 1분 스피치 + 슬라이드 불릿 → `발표자료.md`

## ③ 웹페이지가 생성한 테스트 시나리오 3개 (기대출력 포함)

### 시나리오 1 · 정상 케이스
- **입력**: `11/6 CB본부-ICT본부 회의. 참석: CB 김민정 팀장, ICT 박성훈 파트장. 김민정: MIS모형 세그먼트 리포트 11/10까지 작성, 박성훈: 데이터 결측치 점검 후 CB에 11/8까지 전달. 결정: 재학습 여부는 다음주 CB본부장이 최종 결정.`
- **기대출력**: CB본부(김민정: 세그먼트 리포트, 11/10, 확정), ICT본부(박성훈: 결측치 점검, 11/8, 확정). 의사결정 '재학습 여부, 결정자 CB본부장, 기한 확인 필요'. 선행-후행: ICT 결측치(11/8)→CB 리포트(11/10). 부서별 메신저/이메일 초안 포함.

### 시나리오 2 · 애매한 케이스
- **입력**: `어제 영업팀이랑 법무 잠깐 얘기함. NDA 초안 누가 쓸지 얘기하다 말았고, 신한은행 미팅은 다음주쯤? 담당자는 아직 미정인 듯.`
- **기대출력**: 영업본부·법무실 섹션 생성, 할 일 담당자·기한 모두 '확인 필요'. 작성 문서 'NDA 초안'(담당 미배정). 의사결정 'NDA 작성 담당자 지정'은 결정자·기한 확인 필요. 갭 리스트에 '신한은행 미팅 일정 불명확', 'NDA 담당자 미정'.

### 시나리오 3 · 예외/까다로운 케이스
- **입력**: `ㅋㅋ 아까 회의 녹취 개판인데 대충... 경영지원팀장이 뭐라뭐라 KPI 취합하라 했고 ICT는 아 몰라 걍 오류시트 고치라던데 누가 언제인지 모르겠음 ㅎㅎ`
- **기대출력**: 부서 매핑 불확실 → 경영본부·ICT본부 [알 수 없음] 병기, 담당·기한 전부 '확인 필요'. 할 일 'KPI 취합'(경영), '오류시트 수정'(ICT)만 추출, 창작 없음. 갭 리스트에 '회의 제목/날짜/참석자 불명확', '담당·기한 전체 미기재'. 공유 메시지는 재확인 요청 형태.

→ 이 3개 입력은 `회의록/샘플02~04`로 저장하여 두 접근법 공통 테스트에 사용.

## ⑤ Claude Code 개발 가이드 (웹페이지 원문, 7단계)

> ⚠️ **핵심 관찰**: 이 가이드는 **Anthropic Python SDK로 Claude API를 호출하는 Python CLI 스크립트**를 만들라고 안내합니다.
> 즉 **API 키가 필요**합니다. 사용자의 제약(API 키 없음 · 로컬 로그인만 사용)과 맞지 않으므로,
> 접근법 A의 앱은 이 가이드를 그대로 따르지 않고 **A가 생성한 시스템 프롬프트를 그대로 사용하되, 실행 형태만 코크핏 웹앱 + Claude Code 엔진으로 대체**한다. (형태 통일 → 공정 비교)

1. **Claude Code 설치**: `npm install -g @anthropic-ai/claude-code` (Node 18+)
2. **프로젝트 폴더 생성**: `mkdir my-agent && cd my-agent`, 예시 파일 복사 후 `claude`
3. **첫 프롬프트 복붙**: (정의서 + 시스템 프롬프트 전체) + "위 내용을 바탕으로 Python 스크립트를 만들어줘. 조건: ① Anthropic Python SDK 사용(pip install anthropic) ② 시스템 프롬프트를 코드에 포함 ③ 사용자 입력→Claude API 호출→결과 출력 ④ 상단 사용법 주석 ⑤ 업로드 파일 읽어 처리"
4. **파싱 로직 추가**: "샘플01_불규칙메모.txt 형식 분석해서 자동으로 읽고 처리하도록 업데이트"
5. **실행/디버그**: "python main.py 실행, 에러 나면 고쳐줘"
6. **기능 추가**: "결과 output.txt 저장 / 완료 메시지 한국어 / 빈 입력 안내"
7. **배포 준비**: "requirements.txt, README.md 작성"

## 접근법 A 총평 (진행 관점)
- 강점: 진단→추천→프롬프트→테스트→발표→개발까지 **매우 매끄러운 온보딩**. 프롬프트 품질도 준수(4대 항목·확인필요·JSON 포함).
- 약점: 최종 개발 가이드가 **API 키 기반 Python CLI로 고정** → 사용자 제약과 불일치. 앱 UX/공유 화면에 대한 안내는 없음(프롬프트/CLI까지만).
